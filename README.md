# JIANZI（见字）

> Meet the person behind the words.

## 品牌信息

- **品牌名**：JIANZI
- **中文展示**：见字
- **英文副标题**：Meet the person behind the words.
- **产品介绍句**：A quiet stream of thoughtful Zhihu answers and the people who wrote them.
- **中文对应句**：在知乎，遇见认真写字的人。

## 产品场景

很多时候，用户打开内容平台时并没有一个明确的问题，只是想读点东西，却不知道从哪里开始。JIANZI 提供一张卡片桌：用户在卡片之间移动，偶遇一个没有主动搜索过的话题，也遇见写下回答的那个人。

卡片展示问题标题、作者信息、原文开头和一句真实的推荐理由。用户可以根据这段引荐决定是否继续，感兴趣时直接进入知乎原文，慢慢读完作者写下的内容。

JIANZI 负责让用户遇见内容和作者，深度留给知乎原文。它不替用户总结答案，也不把长回答加工成知识卡片。

## MVP

- 展示卡片桌：中央卡片清晰，周围卡片逐渐淡出。
- 浏览卡片：支持拖动、方向键或点击切换。
- 展示卡片内容：问题标题、作者信息、原文开头、一句推荐理由、可选精选评论和基础元信息。
- 记录喜欢与不喜欢，并用简单规则适度引入用户尚未了解的领域。
- 点击卡片后翻面并放大成专栏视图，读完在底部跳转知乎原文（新标签页）。
- 为作者信息缺失、评论缺失、空内容和接口失败提供降级状态。

## 产品原则

1. **遇见一个人**：优先呈现回答背后具体、认真写作的作者。
2. **保留原文**：不在产品内生成摘要、答案或复习材料。
3. **扩充广度**：记录用户偏好，也适度引入陌生领域。
4. **先保证体验**：内容池以预生成或缓存数据为主，保证 Demo 可以稳定体验。

## 内容与数据

- 内容来自知乎开放平台 API 和人工精选内容。
- API 调用需要缓存，并遵守知乎开放平台的调用频率与额度限制。
- 不爬取知乎站点，不批量滥用站内用户数据。
- Access Secret、`app_key`、OAuth token 等凭证不得进入代码、前端响应、日志、截图或演示视频。
- 作者信息和精选评论可能缺失，界面需要支持对应的空状态。
- 内容池由 `scripts/build-pool.mjs` 离线生成，产物是 `content/pool.json`。第一道采集门槛是纯规则，第二道文本特征层也是纯规则且离线，只有第三道模型评分需要网络和凭据；没有凭据时前两道照常工作。

## 本地命令

```bash
npm run dev                # 本地开发
npm run build              # 生产构建
npm run lint               # eslint
npm run check:features     # 文本特征层的自检，纯 node，无框架

# 重建内容池（默认读 ../pool-raw，即主仓库的种子目录）
node scripts/build-pool.mjs

# 接模型评分时，凭据只走环境变量，不落盘
LLM_BASE_URL=https://api.example.com/v1 \
LLM_API_KEY=... \
LLM_MODEL=... \
LLM_CONCURRENCY=2 \
LLM_BATCH_SIZE=6 \
node scripts/build-pool.mjs
```

模型评分不是必跑项：不配 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 时脚本仍然产出完整的池子，只按文本特征过滤。评分结果缓存在 `content/scores.json`，按卡片 id 存，改 prompt 或换模型会自动重评。

评分按批进行，每次送 `LLM_BATCH_SIZE` 条（默认 6），每条正文截到 `LLM_EXCERPT_CHARS`（默认 1200）。批量不只是省钱：在提示词里放了一好一坏两条基准卡做刻度，模型一次看多条时尺度更稳。某一批少返回了 id，那几张会单独再问一次。单次调用超时默认 180 秒，免费端点上一条卡实测要 100 秒上下。

## 开发状态

项目目前处于 MVP 开发阶段。前端优先完成可独立演示的卡片桌和专栏视图，再通过清晰的数据边界接入后端内容池与知乎 OAuth。

技术栈为 Next.js 全栈 + Vercel，单域名同时承载前端与知乎 OAuth 回调。视觉风格为纸张拟物 + 报纸质感。部署方式会随代码落地补充。
